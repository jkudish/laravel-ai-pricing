## How bases are qualified

- **Native OpenAI** follows the existing `openai:gpt-6.1-sol-standard-short/-long` convention. Every current model has batch, flex, fast, ultrafast, regional or FedRAMP variants at other rates, so each gets a `-standard` basis and its generic ID is fallback-blocked. Models with a published long-context tier get `-standard-short` (≤ 272,000 input tokens) and `-standard-long` (> 272,000; the higher rates apply to the full request). Models without one, either because maximum input is 272,000 or because OpenAI publishes flat rates, get a single `-standard` basis.
- **Cache writes**: GPT-5.6 and later bill cache writes at 1.25× input, and the pricing table lists them. For earlier models the caching guide says there is "no additional cache-write charge" and that "input tokens use the uncached-input, cached-input, or cache-write rate". Those entries therefore price `cache_write_input_tokens` at the uncached input rate, so a reported write count does not leave the quote partial. Pro models publish no cached-input rate, so both cache units stay unpriced.
- **Reasoning** is output usage everywhere. OpenAI publishes no separate reasoning rate, and `reasoning.mode: pro` bills at the model's standard token rates.
- **Web search** uses the existing `web_searches` unit. For reasoning models (all GPT-5.x/6.x), both `web_search` and `web_search_preview` cost USD 10 per 1,000 calls, so native entries price it at `10` per `1000`. Non-reasoning models (`gpt-4.1*`, `gpt-4o*`, `chat-latest`) leave it unpriced because `web_search_preview` costs USD 25 per 1,000 there. No adapter maps OpenAI `web_search_call` counts today, so callers must pass `web_searches` themselves.
- **OpenRouter**: bound bases follow the `openrouter:google/gemini-3.1-flash-lite-standard-max` precedent and are named `openrouter:openai/{id}-standard-max[-short|-long]`. Each prices every request at the most expensive *default-routed* endpoint. Default-routed means every endpoint except the opt-in `openai/flex`, `openai/fast` and `openai/ultrafast` tags; regional `azure/us`, `azure/eu`, `azure/swedencentral` and `amazon-bedrock/*` count as default-routed, as in the Gemini precedent. OpenRouter's long-context override starts at `min_prompt_tokens: 272000`, which is inclusive, so `-short` means < 272,000 prompt tokens and `-long` means ≥ 272,000. The direct API's boundary is > 272,000.

## 6. Conflicts and uncertainties

1. **`openai/gpt-5.6-sol` on OpenRouter conflicts with OpenAI.** The model-level catalog and the `openai` endpoint show USD 2/10 (cache 0.2/2.5) with `discount: 0.5`. OpenAI's direct promotional price is 4/20 (cache 0.40/5), which the `azure` endpoint charges, and regional endpoints charge 4.4/22. The same holds for `gpt-5.6-sol-pro`. The proposed `-standard-max` bases price at the regional rates, and the generics are blocked. It's unclear whether OpenRouter's displayed `prompt` already includes the discount. The `azure` comparison suggests it does. Either way the bound basis is an upper bound.
2. **The live OpenRouter catalog under-prices long prompts for every model with an override.** `OpenRouterPricingSource::rates()` ignores `pricing.overrides` (the ≥272,000-token 2× input and 1.5× output rates). Any unblocked generic with an override is therefore under-priced for long prompts, including `openai/gpt-5.5-pro` and `openai/gpt-5.4-pro`, which section 3 marks "sufficient" below 272,000. I recommend a package fix: read `overrides` or treat their presence as unsupported. It is outside this research's scope.
3. **Pre-GPT-5.6 cache writes.** OpenAI says "no additional cache-write charge" and that input tokens bill at one of three rates, so native entries price writes at the uncached input rate, a conservative choice. OpenRouter's caching guide says they have "no cost", so the pre-5.6 OpenRouter bases leave `cache_write_input_tokens` unpriced, matching the Gemini precedent. If you'd rather leave native writes unpriced too, delete that line from the 12 pre-5.6 native entries that price them (every non-pro model up to `gpt-5.5`, plus `chat-latest` and `gpt-rosalind-research`). A reported write count would then make the quote partial.
4. **OpenRouter's caching guide is stale on cache reads.** It says OpenAI cache reads cost 0.25× or 0.50×. The catalog and OpenAI both say 0.1× for GPT-5.x and later, and 0.05× for `gpt-6.1-sol`. The entries use the catalog and OpenAI values.
5. **Regional endpoints are assumed to be default-routed** on OpenRouter, following the Gemini precedent. If OpenRouter only routes there on request, base rates would suffice and every `-standard-max` basis overstates by 10%.
6. **Context threshold mismatch.** OpenAI's direct long tier starts above 272,000 input tokens. OpenRouter's `min_prompt_tokens: 272000` is inclusive, so the native and OpenRouter `-short` bases differ by one token at the boundary.
7. **`gpt-5.6-sol` promotional pricing** is guaranteed only "at least through November 21, 2026". The model page's "20% input and 33% output reduction" implies a prior USD 5/30. The entry notes say to re-review on or before 2026-11-21.
8. **The pricing page still lists shut-down models** (davinci-002, babbage-002, gpt-3.5-turbo-instruct, gpt-3.5-turbo-1106) after their 2026-09-28 shutdown. I treated the deprecations page as authoritative for availability.
9. **The GPT-5 and o3 alias status is ambiguous.** The deprecation table names only dated snapshots (`gpt-5-2025-08-07`, etc.). It does not use the "snapshot | alias" form it uses elsewhere (for example `o1-2024-12-17 | o1`). Since each alias has no other snapshot, I classified `gpt-5`, `gpt-5-mini`, `gpt-5-nano`, `gpt-5-pro`, `o3` and `o3-pro` as deprecated, with rates listed in section 5 in case you disagree.
10. **Inferred maximum input for `gpt-5.2` and `gpt-5.2-pro`.** Their model pages give a 400,000-token context and 128,000 max output but no "Maximum input tokens" line. The pricing page shows no long tier, so I treated them as single-tier. Same for `gpt-5-pro` (excluded).
11. **Gated models.** `gpt-5.6-cyber` and `gpt-rosalind-research` require OpenAI trusted access. `gpt-rosalind-research` has no model page, so its reasoning and tool support are unverified and web search is left unpriced. Drop either entry if the package shouldn't carry gated models.
12. **Web search on non-reasoning models** is unpriced on both native and OpenRouter bases (`gpt-4.1`, `gpt-4.1-mini`, `gpt-4o`, `gpt-4o-mini`, `chat-latest`). Preview and GA tools differ (USD 25 vs 10 per 1,000), and `gpt-4.1-mini`/`gpt-4o-mini` GA search adds a fixed 8,000-input-token block per call. OpenRouter falls back to Exa for `gpt-4o*`.
13. **Web-search call semantics.** Only `web_search_call` items whose action is `search` are billed; `open_page` and `find_in_page` are not. Search content tokens bill at the model rates and should already be included in reported input usage, but this is unverified without a live call.
14. **Regional uplift eligibility.** OpenAI charges the 10% uplift only for models released on or after 2026-03-05 *that are eligible for data residency*. Entries exclude regional and FedRAMP endpoints generically rather than asserting each model's eligibility.
15. **The Daybreak aliases** (`gpt-daybreak-blue-latest` → `gpt-5.6-sol`, `gpt-daybreak-red-latest` → `gpt-5.6-cyber`) have no row on the pricing page. They inherit their target's price, but they are blocked because their targets are tiered.
